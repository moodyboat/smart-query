# 业务本体模型指引

## 概述
系统中已配置业务本体模型，包含指标定义、维度层次和业务术语。在回答数据分析问题时，优先使用本体模型来理解业务语义。

## 指标查询规则

### 基础指标 (basic)
基础指标直接对应数据库字段。查询时使用指标定义中的聚合方式和来源表：
- 格式: `SELECT {aggregation}({source_column}) FROM {source_table}`
- 聚合方式: sum, count, avg, max, min, count_distinct

### 派生指标 (derived)
派生指标有计算公式。使用 formula 字段中的公式替换到 SQL 中：
- 公式中可能引用其他指标: `{metric.指标名}`
- 解析时先替换引用指标为对应的 SQL 表达式

### 复合指标 (composite)
复合指标由多个指标组合计算。使用 formula_sql_template 字段：
- 模板中 `{metric.xxx}` 需要替换为对应指标的完整 SQL 子查询

## 维度下钻
维度可以按层次结构下钻:
- 层次结构: 如 地区 → 省 → 市 → 区
- 下钻查询: 在 GROUP BY 中使用更细粒度的维度字段
- 上卷查询: 在 GROUP BY 中使用更粗粒度的维度字段

## 归因分析
当用户问"为什么 XX 变化"时:
1. 计算指标的变化量
2. 按各维度分组计算各组的变化贡献
3. 找出贡献最大的维度值
4. 示例: "华东区销售额增长主要由上海贡献 (+15%), 部分被浙江下降 (-3%) 抵消"

## 业务术语
用户可能使用业务术语而非精确指标名:
- 同义词匹配: "毛利占比" = "毛利率"
- 术语 → 指标映射: 找到映射的 metric_id 后使用对应指标的查询规则
- 如果术语没有映射到指标, 使用 mapping_rule 中的自然语言描述来生成 SQL

## 多指标联查
多个指标同时查询时:
1. 确认所有指标的来源表是否相同
2. 如果来源表不同, 找到关联键并使用 JOIN
3. 如果时间粒度不同, 统一到最细粒度再聚合
4. 示例: 月销售额 + 月订单数 → JOIN on 月份, 分别 SUM(amount), COUNT(DISTINCT order_id)
